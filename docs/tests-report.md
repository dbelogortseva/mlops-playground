# Проверка контракта, smoke и детерминизма

В `tests/test_predict_contract.py` находятся шесть тестовых функций.
Первая проверяет четыре варианта мусорного тела, поэтому pytest запускает
девять отдельных случаев. Используются настоящий артефакт модели и FastAPI
TestClient; запуск сервера и PostgreSQL для этого задания не требуется.

| Тест | Что проверяется |
| --- | --- |
| `test_contract_garbage_returns_422` | Текст вместо JSON, незакрытый JSON, массив и null дают 422 |
| `test_contract_extra_field_returns_422` | Лишнее поле даёт 422 и ошибку extra_forbidden |
| `test_contract_wrong_type_returns_422` | Строка garbage вместо целого месяца даёт 422 |
| `test_smoke_response_range_and_types` | Ответ 200, все четыре поля и правильные типы; прогноз и время конечные и >= 0; UUID4 |
| `test_smoke_missing_features` | Допустимые null в признаках дают 200 и конечный неотрицательный прогноз |
| `test_determinism_same_input_same_prediction` | Один и тот же JSON дважды даёт точно одинаковые prediction и model_version |

Модель прогнозирует количество заказов, поэтому допустимый диапазон —
конечное число >= 0. Это регрессия: диапазон [0, 1] и целочисленность
для её ответа не требуются. Верхняя граница предметной областью не задана.

Детерминизм относится к результату модели. `request_id` различается для
каждого запроса, а `latency_ms` зависит от времени выполнения, поэтому полное
равенство JSON-ответов было бы неверным требованием для этого API.

## Команды для отчёта

В PowerShell из основной папки проекта:

```powershell
cd C:\Users\Даша\Desktop\Courses\ML_PRO\dz1\mlops-playground
uv sync --locked
uv run pytest tests/test_predict_contract.py -v
uv run pytest
```

Первый запуск pytest показывает по именам проверки трёх обязательных сюжетов.
Ожидается **9 passed**. Второй запускает все тесты проекта:
локальный результат — **54 passed, 1 skipped**, код завершения 0.
Пропущен только отдельный интеграционный тест логирования в PostgreSQL,
если не задан `TEST_DATABASE_URL`; ни одна проверка этого задания не пропущена.
Два предупреждения об устаревших интерфейсах зависимостей TestClient
не являются ошибками тестов.

Если TEST_DATABASE_URL остался от предыдущего задания, для запуска без БД
сначала выполните:

```powershell
Remove-Item Env:TEST_DATABASE_URL -ErrorAction SilentlyContinue
```

Приложите к отчёту скриншот подробного запуска девяти случаев,
скриншот итогового результата `uv run pytest` и ссылку на коммит с тестами.
Повторять вручную запросы в Swagger для этого пункта не обязательно.
