# API прогноза количества заказов

## Запуск и ручная проверка

Все команды выполняйте из корня репозитория с актуальным коммитом.

```powershell
uv sync --locked
uv run uvicorn mlops_playground.api:app --host 127.0.0.1 --port 8000
```

Первый терминал оставьте открытым. Остановка сервера — Ctrl+C.
Откройте http://127.0.0.1:8000/docs в браузере. В `POST /v1/predict`
нажмите **Try it out**, вставьте содержимое `examples/predict.json`,
затем нажмите **Execute**. Встроенный пример Swagger тоже допустим:
он описывает начало истории, когда лаги ещё неизвестны.

Во втором терминале PowerShell, также из корня репозитория:

```powershell
curl.exe -i http://127.0.0.1:8000/health
curl.exe -i http://127.0.0.1:8000/ready
curl.exe -i -X POST http://127.0.0.1:8000/v1/predict -H "Content-Type: application/json" --data-binary "@examples/predict.json"
```

Используйте именно `curl.exe`: в Windows PowerShell имя `curl` может быть
псевдонимом другой команды.

Проверка пропусков и двух ошибок валидации:

```powershell
curl.exe -i -X POST http://127.0.0.1:8000/v1/predict -H "Content-Type: application/json" --data-binary "@examples/predict_missing.json"
curl.exe -i -X POST http://127.0.0.1:8000/v1/predict -H "Content-Type: application/json" --data-binary "@examples/predict_invalid_extra.json"
curl.exe -i -X POST http://127.0.0.1:8000/v1/predict -H "Content-Type: application/json" --data-binary "@examples/predict_invalid_bounds.json"
```

Первая команда должна вернуть 200, следующие две — 422.

## Точки API

| Метод и путь | Назначение | Результат |
| --- | --- | --- |
| `GET /health` | Процесс приложения работает | 200, `{"status":"ok"}` |
| `GET /ready` | Модель загружена и прошла проверку | 200 и версия модели; иначе 503 |
| `POST /v1/predict` | Прогноз количества заказов на один день | 200; неверный запрос — 422; нет модели — 503 |
| `GET /docs` | Swagger UI с интерактивной отправкой запросов | 200 |

Спецификация OpenAPI доступна по `/openapi.json`, альтернативная документация —
по `/redoc`. При внутренней ошибке прогнозирования возвращается 500 без
подробностей исключения; подробности записываются в журнал сервера.

## Контракт признаков

Запрос — плоский JSON-объект с 68 признаками из `make_features`.
Имена и порядок проверяются при загрузке по `metadata.feature_columns`
и `estimator.feature_names_in_`.

| Признаки | Ограничения | Пропуск / null |
| --- | --- | --- |
| `day_of_week` | Целое от 0 (понедельник) до 6 | Нет |
| `month` | Целое от 1 до 12 | Нет |
| `is_weekend` | Целое 0 или 1 | Нет |
| `dow_sin`, `dow_cos`, `year_sin`, `year_cos` | Числа от -1 до 1 | Нет |
| `lag_1`, `lag_7`, `lag_14`, `lag_28` | Целое >= 0 | Да |
| `rolling_mean_*`, `rolling_std_*` | Число >= 0 | Да |
| `raw_price_*`, `raw_qty_ordered_*`, `raw_MV_*` | >= 0; счётные min/max/sum — целые | Да |
| `raw_grand_total_*`, `raw_discount_amount_*` | Конечные числа; std >= 0 | Да |
| `raw_Year_mean/median/min/max` | От 1 до 9999; min/max — целые | Да |
| `raw_Month_mean/median/min/max` | От 1 до 12; min/max — целые | Да |
| `raw_Year_std`, `raw_Month_std` | Число >= 0 | Да |
| `raw_Year_sum`, `raw_Month_sum`, `raw_*_nunique`, `raw_rows_count` | Целое >= 0 | Да |

`extra="forbid"` запрещает неизвестные поля. Включена строгая проверка типов:
строка `"12"` не заменяет число 12, а `true` не заменяет 1.
NaN и Infinity в запросе запрещены; используйте `null` для допустимых пропусков.
Поля с пробелами и дефисами сохраняют имена обучающей выборки, например
`"raw_BI Status_nunique"`, через Pydantic aliases.

Основания для ограничений:

- Проверены все 525 строк признаков из обучающей истории в артефакте.
- Календарные признаки не имеют пропусков.
- Лаги имеют 1/7/14/28 пропусков; скользящие статистики — 7/28.
- Каждый `raw_*` имеет пропуск в начале истории из-за `shift(1)`.
- В данных есть отрицательные `grand_total_min` (-1594) и
  `discount_amount_min` (-599.5), поэтому знаковые денежные агрегаты
  не ограничены снизу нулём (кроме стандартного отклонения).
- Максимум обучающей выборки не используется как универсальный верхний
  предел для будущих заказов и денежных сумм.

Пропущенные допустимые поля преобразуются в `np.nan`.
`HistGradientBoostingRegressor` обрабатывает такие значения.

Важно: `raw_*` относятся к **предыдущему дню**, поскольку подготовка данных
использует сдвиг на один день. Лаги и rolling также рассчитываются только
по предшествующей истории. API не рассчитывает их из исходных транзакций:
он вызывает шаг `model` сохранённого pipeline на готовой строке признаков.
Повторная предобработка такой строки привела бы к повторному сдвигу.
Для проверки реализован тест совпадения с полным pipeline на исходной истории.
Межполевая календарная согласованность должна обеспечиваться `make_features`;
схема проверяет типы, обязательность и диапазоны отдельных полей.

## Загрузка модели и ответ

Артефакт `artifact/model.joblib` загружается один раз за запуск `lifespan`
каждого процесса приложения. При нескольких workers каждый загружает свою
копию. Загрузка не выполняется при импорте модуля и не повторяется на запросах.
Перед готовностью проверяются признаки, версия scikit-learn, версия модели
и пробное предсказание. При ошибке приложение сохраняет `/health` и `/docs`,
но `/ready` и корректный `/v1/predict` возвращают 503. После исправления
артефакта нужно перезапустить сервер.

Можно указать другой доверенный локальный артефакт:

```powershell
$env:MODEL_PATH = "C:\path\to\model.joblib"
uv run uvicorn mlops_playground.api:app
```

Чтобы снова использовать путь по умолчанию:

```powershell
Remove-Item Env:MODEL_PATH -ErrorAction SilentlyContinue
```

Существующий артефакт пересохранён с новым путём класса
`mlops_playground.pipeline.DailyFeatures` вместо `src.pipeline.DailyFeatures`.
Модель не переобучалась; все 525 предсказаний до и после совпали точно.
Версия модели сохранена: `1.0.0`. Для десериализации данных внутри артефакта
`pyarrow` включён в основные зависимости.

Пример успешного ответа при локальной HTTP-проверке `examples/predict.json`:

```json
{
  "prediction": 737.6588976441448,
  "model_version": "1.0.0",
  "request_id": "efb42e0e-bf66-4727-b9f5-c4b6caf0f780",
  "latency_ms": 8.003000002645422
}
```

Предсказание — ожидаемое количество заказов, поэтому оно может быть дробным.
`request_id` — новый UUID4 для каждого успешного запроса.
`latency_ms` измеряется через монотонный `perf_counter` от начала обработчика
до подготовки ответа: включает сборку строки и вычисление прогноза,
но не сетевую задержку, валидацию до обработчика и сериализацию ответа.
UUID и время при повторном запуске будут другими.

## Автоматические проверки и отчёт

```powershell
uv run pytest -q
```

Локальный результат 20 сентября 2026 года: **34 passed** на Windows,
Python 3.13.14. Есть два предупреждения об устаревших интерфейсах внутри
зависимостей TestClient; тесты завершились без ошибок.
Проверены схема на всей истории, допустимые пропуски, неправильные типы и
границы, запрет дополнительных полей, NaN/Infinity, уникальные UUID,
совпадение прогноза с pipeline, однократная загрузка через spy на `joblib.load`,
недоступный/повреждённый артефакт, несовместимые признаки и версия scikit-learn.

Дополнительно запущен настоящий Uvicorn и выполнены HTTP-запросы:
`/health`, `/ready`, `/docs`, `/openapi.json` — 200;
оба допустимых примера прогноза — 200; лишнее поле и `month=13` — 422.
После проверки временный сервер остановлен.

Для отчёта приложите:

1. Ссылку на коммит реализации.
2. Скриншот Swagger UI со списком точек и схемой запроса.
3. Ответы `/health` и `/ready`, успешный прогноз со всеми четырьмя полями.
4. Ответы 422 для лишнего поля и неверного месяца, успешный запрос с пропусками.
5. Вывод `uv run pytest -q` и фрагмент `lifespan` из `src/mlops_playground/api.py`.
